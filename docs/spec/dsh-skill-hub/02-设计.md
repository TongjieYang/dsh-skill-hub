# 02 设计 — dsh-skill-hub

> 阶段 2/5 · 定方案 · 判据：数据形状、接口契约、失败模式三节齐全。

## 1. 形态

一个 DSH bundle，两半：

```
dsh-skill-hub/
├─ index.js            # host 半：3 个工具 + 1 条 HTTP 路由
├─ client.js           # browser 半：设置面板「技能中枢」
├─ cordis.patch.yml    # bundle 入口声明
├─ lib/                # 纯函数，零依赖，node 可单测
│  ├─ frontmatter.js   解析 SKILL.md
│  ├─ scan.js          扫根 → skill 列表 + 容器 + shadowed
│  ├─ classify.js      10 类 + 关键词打分 + override
│  ├─ teams.js         内置 4 团 + 用户团读写
│  ├─ keygen.js        三平台入匙脚本（占位符）
│  └─ store.js         ~/.agents/skill-hub 读写
├─ locale/{zh,en}.json 显示元数据
├─ icon.svg
└─ docs/DETAIL.md
```

`skills[].category` 永远存在；`overridden` 标记是否被 config 覆盖。
**keys 永不含 secret 字段**——结构上没有这个位置。

## 3. 接口契约

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | `/skill-hub/api/state` | — | 上面那个对象（每次现扫，260 目录 ~10ms） |
| POST | `/skill-hub/api/classify` | `{ name, category }` | `{ ok:true }` 写 `config.json.overrides`；`category:null` 删除覆盖 |
| POST | `/skill-hub/api/team/save` | `{ team }` | `{ ok:true, team }` 写 `teams/<id>.json` |
| POST | `/skill-hub/api/team/delete` | `{ id }` | `{ ok:true }` 删用户团文件（内置团只允许 reset） |
| POST | `/skill-hub/api/team/reset` | `{ id }` | 删用户覆盖，回落内置 |
| POST | `/skill-hub/api/keys/add` | `{ env, service, account, platform, note }` | `{ ok:true, script:{…} }` 记元数据 + 返脚本模板 |
| POST | `/skill-hub/api/keys/remove` | `{ env }` | `{ ok:true }` |

`script` 形状（`secretPlaceholder: "__SECRET__"`）：
```jsonc
{ "platform":"darwin", "placeholder":"__SECRET__",
  "add":"security add-generic-password … -w '__SECRET__' -U",
  "read":"export WEREAD_API_KEY=\"$(security find-generic-password … -w)\"",
  "remove":"security delete-generic-password …" }
```
客户端把 `__SECRET__` 换成用户输入的密钥后展示。

**agent 工具**（host 半注册，编译形态，不 import dsh 包）：

| 工具 | 参数 | 返回 |
|---|---|---|
| `skill_hub_scan` | `{ query?, category?, limit? }` | 分类统计 + 命中的 skill 名单（name/source/category/description 首 100 字） |
| `skill_hub_team` | `{ team, stage? }` | 整团 SOP：目标 / 角色（职责 + 绑定 skill + 交付物）/ 阶段；`stage` 指定时只回该阶段用到的角色 |
| `skill_hub_key_script` | `{ env, service, account?, platform?, note? }` | **只回占位符模板**；描述里写明「真实密钥让用户自己在 UI 填，不要贴进对话」 |

工具描述里写死路由规则，让模型自己知道什么时候调用：
- 用户问「有哪些 skill / 该怎么组合 / 做某类视频怎么排」→ `skill_hub_scan` + `skill_hub_team`。
- 用户要给某服务配 key → `skill_hub_key_script`，然后把命令交给用户执行。

## 4. 分类算法

`classify(skill)` 打分：
1. **名前缀规则**（强，命中即 100 分）：如 `^lark-` → collab、`^amap`/`高德` → map-travel、`^baoyu-` → 视名字再分 image-design/writing。
2. **关键词表**：每类 15–30 个中英关键词，命中 name+description 每个 3 分，取最高；同分按类别声明顺序（越具体越前）。
3. **兜底 `other`**。`overrides[name]` 存在时直接返回覆盖值，跳过上面两步。

## 5. 专家团

一个团 = `{ id, title, goal, builtin, roles[], stages[] }`；
`roles[i] = { id, title, duty, skills[], deliverable }`；
`stages[i] = { id, title, deliverable, roleIds[] }`。
内置团写死在 `lib/teams.js`（代码即真源），用户团落 `~/.agents/skill-hub/teams/<id>.json`；
同名用户团覆盖内置，`reset` 只删用户文件。
校验：`skills[]` 里主库不存在的记入 `missingSkills`，界面与该团的 `skill_hub_team` 输出都会标红，避免「团引用了不存在的 skill」静默失败。

内置 4 团：
- `daohuo-video` 带货视频团 — 选题情报 / 脚本钩子 / 分镜与素材 / 配音与成片 / 发布与投放（5 角色）
- `kepu-video` 科普视频团 — 知识考据 / 结构化讲解 / 视觉化 / 成片质检（4 角色）
- `app-builder` 应用开发团 — 需求澄清 / 架构与接口 / 实现 / 测试与验收 / 发布（5 角色）
- `xhs-ops` 小红书运营团 — 选题日历 / 图文笔记 / 标题封面 / 数据复盘（4 角色）

## 6. 失败模式与处理

| 失败 | 处理 |
|---|---|
| `webServer` 服务不存在（headless profile） | `ctx.inject(['webServer'], …)` 使路由半边不激活，工具仍可用 |
| 扫描根不存在 | `roots[].exists=false`，不报错；`warnings` 里记一条 |
| SKILL.md front-matter 损坏 | 该条仍列出，`description` 退化为空串，`warnings` 记路径 |
| 同名 skill 多份 | 按 rank 升序保留第一份，其余进 `shadowed`（与 DSH skill provider 的 rank 语义一致） |
| 写 config/teams 失败（权限） | 返回 `{ ok:false, error }`，界面显示错误条，不静默 |
| 用户在 UI 填了密钥但没执行命令 | 只是不生效；`keys.json` 里有元数据、`security find-generic-password` 会报 not found → 界面提示「命令还没跑」 |
| 团引用了不存在的 skill | `missingSkills` 非空，界面黄条提示 |

## 7. 安全边界（硬约束）

1. **host 侧永不含密钥**：`keygen.js` 里的 `__SECRET__` 是字面占位符，没有 `process.env` 读密钥的路径。
2. **不执行任何 shell**：全仓无 `child_process` / `exec` / `spawn`；脚本只生成、只展示。
3. **secret 不出浏览器**：输入框的值只存在于 React state，替换占位符后写入 `navigator.clipboard`，不 fetch、不 localStorage。
4. **落盘只有元数据**：`keys.json` 的 schema 无 secret 字段；`POST /keys/add` 只接受五个元数据字段。
