## 已知边界

- `/skill-hub/api` 与其它插件路由一样不受 `dsh-client-connection` 的鉴权保护，仅绑定 loopback。它不接触任何 secret（密钥只存在于浏览器内存），但仍建议不要把它暴露到非 loopback 地址。
- 专家团里绑定的 skill 名是本机现状的快照；主库改名后界面会标 ⚠️ 缺失。
- 分类是启发式，不是语义分类；错分可手动覆盖，覆盖写进 `config.json` 永久生效。

### 自测发现的两个真问题（已修）

1. **所有写操作 405**：`/skill-hub/api` 用 `resource(request)` 注册，而 DSH 的 webserver 对 `resource` 只放行 `GET`/`HEAD`（`README.md:63`、`lib/index.js:243/421/592-601`），POST 一律 405 且不读 body。用户点「生成命令」看到的是红色 `接口返回的不是 JSON（HTTP 405）`。
   修法：改注册 `handler(req, res)`，自己读 body（1 MB 上限）、解析 JSON、跨站（`Sec-Fetch-Site: cross-site`）回 403。
2. **Key 表单静默失效**：「环境变量名」的 `form.env` 初值是空串，但输入框 placeholder 是 `WEREAD_API_KEY`，看起来像已填；生成按钮 `disabled: busy || !form.env.trim()`，用户不点输入框直接点按钮毫无反应也没有提示。
   修法：placeholder 改成 `例如 WEREAD_API_KEY`，环境变量名为空时在按钮下方常显一段说明；另加错误边界，组件抛错时直接显示报错而不是留一个空白面板。

- 第一版 `Mod+Alt+K`：控制台报 `Conflicting shortcut defaults: skill-hub.open and session.search ('web:macos')`——跨 profile 冲突会让整条注册失败，于是只保留 desktop 三个 profile。
- 改成 `⇧⌘K`：`⌥+字母` 在 macOS 是死键，快捷键服务规定 dead key 直接放过，所以 `⌘⌥K` 永远不触发。
- 再补 `listenLocally()`：同一组合键挂 DOM `keydown`，给 Web 端和原生桥不接管的情况兜底；`openSection()` 幂等，两条路径都走也不出问题。
- 已知限制：这台机器的桌面版对「插件注册的默认键位」目前不投递按键（`⌘B`、`⌘/` 这类内建键正常），所以默认值可能按了没反应；在快捷键面板里重新指定一次即可——那次写入会触发原生键位表重新同步。

## 0.2.7 · 快捷键真正生效（2026-11-19）

上一版说「桌面版不投递插件注册的按键」——**结论错了**，撤回。

- 真正原因：`openSection()` 从 `entry.options.store` 取设置外壳的根 store，而骨架把 store 挂在**条目本身**（`entry.store`）。取不到 → `actions` 为 undefined → 静默 return false，所以快捷键的 `resolve().run()` 确实执行了，只是什么都没发生。
- 定位方式：在 `openSection()` 里把 `entries()`/`options`/`actions` 的形状写进一个固定定位的调试浮层（不依赖 DevTools，DevTools 停靠时会抢键盘），一次点击就看到 `optKeys= / act=none`。
- 修法：`entry.store ?? entry.options.store`。修完实测：关闭设置 → 按 `⇧⌘K` → 设置直接落在「技能中枢」。
- 顺带加了 `conversation.input.left` 的 `技能` 按钮（输入框工具行，`完全权限` 右边），点一下同样直达——不用记键位。
- 测试仍 90/90；`/tmp` 下的调试浮层代码未提交（已确认 `grep debugSay client.js` 为空）。
